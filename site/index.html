为什么不直接 wget 加 tarWhy not just wget and tar

Qlib 的说明推荐用一行 wget 下载社区数据包。平时没问题，直到遇到这些情况： Qlib's README suggests a one-line wget of the community release. That works until one of these happens:

  • 下载到一半断了The download breaks halfway 解压出半截数据，或者旧数据已被覆盖才发现失败。 You extract half a dataset, or find out after the old one is already overwritten.
  • 上游修正后重新发布The release gets corrected 上游发现数据错误后，用同一个日期重新发布（#163）。只看日期永远拿不到修复。 Upstream republishes a date after fixing data (#163). Comparing dates alone never picks up the fix.
  • 每次都下载 550 MBEvery check costs 550 MB 即使什么都没变。qlib-sync 先读一个 500 字节的清单。 Even when nothing changed. qlib-sync reads a 500-byte manifest first.

investment_data 自己的说明给出了手动校验流程（manifest 加 validate_archive.py --require-publishable）。qlib-sync 每次更新都直接运行这个校验器的原文，并用对照测试证明两边结论一致；在此之外补上自动跳过、整体切换和失败回滚。默认必须通过校验，无法校验时不会安装。 The investment_data README describes a manual check with the manifest and validate_archive.py --require-publishable. qlib-sync runs an unmodified copy of that validator on every update, with tests showing both reach the same verdicts, and adds the skip, the atomic swap, and the rollback. Verification is required by default: what cannot be verified is not installed.

这些校验能挡住损坏、不完整或被篡改的数据包，挡不住上游正常发布的数据里本身的数值错误。需要时可以用 --keep-backup 保留一份旧数据。 These checks catch broken, truncated, or tampered packages. They cannot catch wrong values inside a correctly published release; keep a rollback copy with --keep-backup if you need one.

在 notebook 里用From a notebook

回测前确保数据是最新的，原来的 Qlib 代码不用改。 Make sure the data is current before a backtest. Your Qlib code stays the same. 

from qlib_sync import update_cn

result = update_cn()   # raises UpdateError on failure; existing data unchanged
print(result.latest_date, result.new_trading_days)

import qlib
qlib.init(provider_uri="~/.qlib/qlib_data/cn_data")
